# Промпт калибровки маршрутов на своих задачах

Скопировать агенту в новую сессию, подставив свои значения в квадратных скобках.

---

Проведи калибровку маршрутов на моих реальных задачах. Маршруты уже настроены: посмотри
`hermes delegation config --show` и возьми оттуда имена и модели.

Параметры:
- файлы с задачами: [папка, например C:/Users/<я>/work/calibration]
- маршруты для сравнения: [workhorse, fast, docs, deep]
- число задач: [8]

Порядок работы:

1. Собери 8 задач из моих файлов. Нужны разные классы: справка/выжимка по документу, протокол или
   регламент по шаблону, сравнение нескольких предложений в таблицу, извлечение структуры из PDF или
   скана, проверка утверждений по первоисточнику, черновик делового письма, разбор чужого вывода,
   сборка чисел из нескольких источников. Если файлов меньше, дополни задачами по их мотивам, но
   данные не выдумывай: помечай такие задачи как синтетические.
2. Для каждой задачи зафиксируй один и тот же промпт (файл `prompts/<номер>.txt`) и одинаковый
   набор входных файлов. Промпт не должен упоминать модель.
3. Прогони каждую задачу по каждому маршруту через `delegate_task` с `option=<маршрут>`. Один
   прогон – один субагент, без дополнительных подсказок и без повторных попыток. Результат каждого
   прогона сохрани в `runs/<номер>/<код>.md`, где `<код>` – случайная метка из четырёх символов,
   выданная заранее; соответствие «код → маршрут» запиши в `runs/key.json` и не открывай его до
   шага 5.
4. Зафиксируй по каждому прогону: время, число шагов, если доступно – сколько списано из лимита
   (`usage` в ответе) и во сколько обошёлся бы по прайсу.
5. Слепая оценка: открой `runs/` вперемешку, не заглядывая в `key.json`. По каждой задаче оцени все
   варианты по рубрике 0–2: полнота, фактическая точность, формат и структура, качество русского,
   отсутствие выдумок. Отдельно отметь, сколько правок пришлось бы внести вручную. Сложи баллы в
   `scores.md`, и только потом открой ключ и подпиши маршруты.
6. Сведи итог: таблица «задача × маршрут» с баллами, временем и ценой; затем сводка по маршрутам:
   средний балл, средняя цена, число задач, где маршрут лучший.
7. Дай вывод: какие маршруты подтвердились, какие надо переставить, где нужен новый маршрут, что
   делать нельзя. Отдельно назови задачи, где разница между маршрутами меньше 10 %, – там решает
   цена, а не качество.

Ограничения:

- Не смешивай в оценке модели знания о бенчмарках: оценивай только текст результата.
- Не подсказывай субагенту, какая модель ему назначена.
- Если прогон упал по лимиту или таймауту, отметь это как отдельный исход, а не как низкое качество.
- Не используй конфиденциальные данные, персональные данные и внутренние документы с грифом:
  калибровка идёт на обезличенных или публичных материалах.
- Итог – два файла: `calibration.xlsx` (таблица баллов и цен) и `calibration.md` (выводы и правки
  маршрутов). Ничего в конфиге не меняй без моего подтверждения.
