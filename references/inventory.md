# Инвентаризация подписки: модели, лимиты, живость

Задача шага: получить файл, из которого можно строить маршруты, не заглядывая в кабинет подписки.

## 1. Список моделей

Почти все подписки дают OpenAI-совместимый эндпоинт:

```bash
KEY=...   # ключ подписки
BASE=https://provider.example/v1

curl -s "$BASE/models" \
  -H "Authorization: Bearer $KEY" \
  -H "User-Agent: route-probe/1.0" \
  -o models.json
```

Что искать в ответе:

- `id` – идентификатор, ровно его надо ставить в конфиг (не человекочитаемое имя);
- `limit.context`, `limit.output` – контекст и максимум вывода;
- `cost.text.input.price`, `cost.text.output.price` – цена за миллион;
- `modalities.input` – текст, изображения, PDF, аудио, видео;
- `capabilities.reasoning.effort` – какие уровни усилия модель принимает;
- `capabilities.tools.supported` – умеет ли вызывать инструменты (без этого агентская роль невозможна);
- `api.chat-completions.base_url` – иногда часть моделей живёт на другом пути, чем остальные.

**Важно:** идентификатор в конфиге может отличаться от каталожного на версию (`-1017`, `-0902`).
Если поставить несуществующий id, провайдер ответит `Model is unavailable`, при этом статус агента
может показывать модель как валидную.

## 2. Лимиты и окна

Ищется в три попытки:

1. Эндпоинт подписки: часто `GET {BASE}/usage`, `/limits`, `/credits`, `/me`. У OpenCode Go работает
   `/zen/go/v1/usage` и отдаёт проценты по rolling / weekly / monthly с датами сброса.
2. Ответ модели: у части подписок в `usage` приходит, сколько запрос списал из лимита
   (`allowance`) и сколько стоил бы по прайсу (`list_cost`). Разница показывает дисконт подписки.
3. Кабинет: если API молчит, лимиты берутся из тарифной страницы (месячный лимит на модель,
   5-часовое окно = 20 %, неделя = 50 %) и записываются вручную с датой.

В инвентарь писать: месячный лимит, цена за миллион, цена за типовой запрос, окно и дата сброса.

## 3. Проверка живости

Минимальный запрос на каждую модель:

```bash
curl -s "$BASE/chat/completions" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -H "User-Agent: route-probe/1.0" \
  -d '{"model":"MODEL_ID","messages":[{"role":"user","content":"OK"}],"max_tokens":5}' \
  -w '\nHTTP:%{http_code}\n'
```

Классификация ответов:

| Ответ | Значение | Что делать |
|---|---|---|
| `200` | работает | в маршруты |
| `403` + страна/регион | гео-блок | исключить, записать дату проверки |
| `403` + endpoint unavailable | сбой у провайдера | перепроверить через сутки |
| `400 coming soon` | анонс без запуска | исключить |
| `400` про приватность/обучение | нужен тумблер в кабинете | решить отдельно |
| `400 missing session header` | прокси требует идентификатор сессии | добавить заголовок (см. ниже) |
| `error code: 1010` | Cloudflare не любит голый скрипт | добавить осмысленный `User-Agent` |

## 4. Два заголовка, без которых половина проверок врёт

- `User-Agent`. Без него Cloudflare отдаёт `error code: 1010` на любой запрос, и это выглядит как
  «весь провайдер недоступен». Ставить что-то похожее на клиент: `opencode/1.0`, `route-probe/1.0`.
- Заголовок сессии. Часть прокси-роутеров (OpenCode Go) требует `x-opencode-session` и без него
  отвечает `MissingSessionID`. Значение – любой стабильный идентификатор беседы.

## 5. Что сохранить в файл

```json
{
  "model": "provider/model-id",
  "status": "ok | geo | coming_soon | privacy | missing_header | error",
  "checked_at": "2026-11-09",
  "context": 1000000,
  "price_in": 0.15,
  "price_out": 0.60,
  "limit_month_usd": 100,
  "window_5h_usd": 20,
  "modalities": ["text", "image"],
  "efforts": ["low", "high", "max"],
  "tools": true
}
```

Дальше этот файл – единственный источник для таблицы маршрутов: без него легко поставить в маршрут
модель, которая в твоей сети не отвечает.
